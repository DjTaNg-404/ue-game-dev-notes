# UE 游戏开发学习笔记

自用的 UE 学习笔记——从竞赛 C++ 向游戏引擎 C++ 过渡的思维沉淀，并逐步扩展到游戏开发中绕不开的工程实践。

## 背景

作者有 ACM/ICPC 竞赛背景（铜牌），对 C++ 语法、STL、指针、模板比较熟悉。但在接触 Unreal Engine 时发现：**竞赛 C++ 和引擎 C++ 之间差的不是语法，而是框架思维**——竞赛代码是一次性的「输入→计算→输出」，引擎代码是在一个持续运行的仿真世界里组织对象、处理事件。

这份笔记记录的就是这个过渡过程中的认知矫正：每遇到一个新概念，先用自己的理解向 AI 描述，再由 AI 判断对错、纠偏，最后把正确认知沉淀成知识笔记。

## 范围与边界

判定标准是「这个概念在写 UE 项目时会不会用到」，而不是「它属不属于游戏开发」。

| | 内容 |
|---|---|
| 纳入 | 引擎机制、Gameplay 框架、构建/调试/性能/协作等工程实践 |
| 纳入 | 通用工程知识（如序列化的版本兼容设计），只要服务于 UE 项目 |
| 不纳入 | 美术、策划、项目管理等不涉及代码的内容 |

范围刻意不追求「游戏开发的一切」——那样目录会失效，笔记退化成碎片堆。

## 笔记特点

- **不是系统教程**，是按自己学习节奏展开的概念笔记
- 每个知识点都是在「自己的理解 + 被纠正后的认知」融合下写成的
- 符合直觉的比喻和例子（如「ACat」「上下左右枚举」等）会被保留进文档
- 面向有 C++ 基础、但没接触过游戏引擎框架的读者
- **不是按顺序写的**：有新理解就随时更新到对应位置，而非按路线图逐阶段填坑
- 内容的**整理、排序、重排均由 AI 完成**，确保最终读起来像教程而非流水账

## 写作与整理流程

1. **学**：接触一个新概念
2. **自述**：先用自己的话把理解讲出来——写错才有纠偏价值
3. **纠偏**：判断哪里对、哪里偏、为什么偏，给出纠正后的表述
4. **沉淀**：把**纠偏后的结论**写进 [inbox.md](./inbox.md)，标上目标卷；不收未经验证的疑问和原始碎片
5. **归位**：按标记归入对应章节，重排理顺全文
6. **回写导航**：更新本文件的全书目录与路线图状态
7. **提交**：一条中文提交信息概括本次增量
